# Как добавить тему или симуляцию

Пособие — обычные файлы без сборки: открыли `index.html` — работает. Всё, что
ниже, делается в текстовом редакторе и проверяется командами из `package.json`.
Полный контракт и история решений — в [ARCHITECTURE.md](ARCHITECTURE.md); здесь —
порядок действий.

## Перед началом

```bash
git clone https://github.com/AkioArai/Phy.Sim && cd Phy.Sim
python3 -m http.server 8977        # или просто открыть index.html
npm i -D playwright@1.56.0 --no-save   # только для браузерных проверок
```

Нижняя граница движка — ES2017 (старые школьные планшеты и Android WebView 58+).
Нельзя: `?.`, `??`, `...` для объектов (пишите `Object.assign`), `catch` без
скобок, `flatMap`, `at`, `replaceAll`. В CSS перед каждым `color-mix`, `min()`,
`max()`, `clamp()` и `dvh` — обычное запасное объявление того же свойства.
`node tests/compat.js` проверит это за секунду.

## Симуляция

1. **Файл.** Симуляции лежат в `js/sims/` по разделам физики. Новый файл
   подключите в `index.html` рядом с остальными (`<script defer src="js/sims/…">`) —
   порядок тегов и есть граф зависимостей. Сборка одного файла и служебный поток
   найдут его сами.
2. **Объект.** `Object.assign(SIMS,{ id:{ … } })` с полями:
   - `title`, `params` — ползунки (`key, label, unit, min, max, step, default`),
     флажки (`type:'check'`), списки (`type:'select', options:[{v,t}]`) и заголовки
     групп (`type:'group'`). У поля или группы может быть `если:p=>…` — тогда оно
     видно только при этом условии;
   - `init(p)` → состояние с `t`; `step(s,dt,p)` — шаг `DT = 1/240` с;
     `s.__stop='текст'` останавливает таймер и показывает сообщение;
   - `draw(ctx,s,v,p)` — в мировых координатах, ось y вверх. Помощники:
     `v.arrow`, `v.label` (сама разводит наезжающие подписи и рисует ореол),
     `v.lw(px)` — толщина в пикселях, `v.c('--var')` — цвет темы, `v.fbd` —
     диаграмма сил (цвет силы берётся из общей таблицы по подписи: `mg`, `N`,
     `Fтр`, `T`, `F_A`, `F`);
   - `fit(p,{W,H})` → `{x,y,scale}` — чтобы всё влезло в кадр;
   - `readouts(s,p)` → `[[подпись, число или строка, единица]]`;
   - `graphs` — `{label, unit, series, get(s,p)->[a,b|null]}`; пометка
     `наклон:i` значит «этот график — производная графика i», её проверяет
     `npm run graphs`;
   - `anchors(s,p)` — опорные точки: по ним работают привязка инструментов,
     стробоскоп, призрак и камера за телом;
   - необязательно: `presets`, `schema:true` (схема — без осей в метрах),
     `timeless:true` (от времени ничего не зависит), `timeUnit:'нс'` (секунда
     сцены изображает другую единицу).
3. **Считайте точно.** Где есть решение в замкнутом виде — берите его; где нет —
   интегратор не хуже Верле или RK4. Энергия, импульс и прочее сохраняемое не
   должны «плыть».
4. **Проверка физики.** В `tests/physics.mjs` добавьте `add(id, параметры,
   кадров, [[подпись, ожидаемое, допуск, почему]], описание)`. Ожидаемое
   считается в тесте независимо от кода симуляции, параметры — некруглые.
   `npm run physics`.
5. **Регресс.** В `tests/regress.js` поправьте счётчик симуляций (и схем или
   «безвременных», если нужно). `npm test`.

## Тема

Темы лежат в `js/topics.js` и собираются в разделы в `SECTIONS`.

1. **Объект** `const T_… = { id, ch, title, key, explore, theory, time, needs,
   why, derivations, formulas, examples, mistakes, checks, links, problems }`:
   - `key` — пять главных утверждений; `explore` — три опыта «сделайте — увидите»;
   - `theory` — HTML; формулы в `$…$`. Знак «меньше» пишите `&lt;`, иначе сборка
     остановится; обратный слэш в строке — двойной (`\\frac`);
   - `needs` — темы, которые нужно знать раньше; они должны стоять выше в оглавлении;
   - `derivations` — `{goal, from, steps:[{tex, why, op:[приёмы]}], sim}`. Цель
     обязана быть одной из формул темы; каждый шаг помечен приёмами из
     `js/ops.js` (подстановка, проекция, малый-угол…);
   - `formulas` — `{tex, kind:'закон'|'определение'|'следствие', note, sim}`;
   - `problems` — `{level:1…5, sim, unit, statement, hint, answer:p=>…}`.
     Ответ считается из параметров симуляции, поэтому у каждого ученика свой.
     Выше первого уровня ответ не должен совпадать с числом на панели показаний.
2. **Раздел.** Добавьте тему в `SECTIONS`; для нового раздела — цвет и значок в
   `ВИД_РАЗДЕЛОВ` (`js/home.js`) и, по желанию, итог в `RECAPS`.
3. **Вход «от вопроса»** — одна-две строки в `ВОПРОСЫ` (`js/learn.js`).
4. **Проверки:**
   ```bash
   npm run curriculum                    # граф предпосылок, выводы, приёмы, имена задач
   npm run curriculum -- --обновить      # если задачи новые — обновить слепок имён
   npm run audit                         # все задачи на 40 случайных наборах
   npm run learn                         # разбор ошибок и карта «Моего пути»
   ```
   Имя задачи выводится из условия. Если правите формулировку уже выпущенной
   задачи — закрепите ей `id`, иначе у всех, кто её решил, сбросится отметка.

## Перед выпуском

`npm test && npm run physics && npm run audit && npm run curriculum`, затем
пройдите [DEVICE-CHECKLIST.md](DEVICE-CHECKLIST.md) на телефоне и планшете.
Версия меняется в четырёх местах: `package.json`, `sw.js` (имя кэша),
`index.html` (meta) и `js/app.js` (`PHYSIM_BUILD`).
