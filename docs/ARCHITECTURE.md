# Архитектура Phy.Sim

Phy.Sim — статическое браузерное приложение без сборки: обычные `<script defer>`
подключаются в строгом порядке и разделяют одну глобальную область видимости.
Это осознанное решение: пособие должно открываться двойным кликом по
`index.html` на любом школьном компьютере, без Node, бандлеров и сервера
(ES-модули с `file://` не работают из-за CORS, классические скрипты — работают).

## Слои и порядок загрузки

Порядок `<script>` в `index.html` — это и есть граф зависимостей (каждый слой
видит всё, что объявлено выше):

```
vendor/katex/*              рендер формул; лежит в репозитории, а не на CDN
js/core.js                  хелперы ($, clamp, константы) + пустой реестр SIMS
js/sims/*.js                каждый файл регистрирует симуляции: Object.assign(SIMS, {…})
js/topics.js                учебный контент: T_* темы → SECTIONS → ALL
js/ops.js                   приёмы выводов: статьи о математике, которой сделаны шаги
js/calc.js                  вычислитель: единицы, погрешность, разбор и решение формул
js/learn.js                 модель ученика: журнал, освоение, повторение, веер ошибок
js/path.js                  панель «Мой путь» (только объявления: зовётся из app.js)
js/home.js                  цвет и значок разделов, шапка темы, главный экран
js/scene.js                 слои сцены: стробоскоп, призрак, камера, легенда сил; доступность, экономия
js/lab.js                   лаборатория: точки с разбросом, МНК, таблица, CSV
js/app.js                   ядро: состояние, холсты, рендер-цикл, весь UI
```

Файлы симуляций между собой не связаны и могут подключаться в любом порядке;
важно лишь, что `core.js` идёт первым, а `topics.js`, `ops.js` и `app.js` —
последними. Без `ops.js` приложение работает, только без меток приёмов:
`app.js` проверяет его наличие (`естьПриёмы()`); так же и с `calc.js`
(`естьВычислитель()`), с `learn.js` (`естьПуть()`).

`path.js` стоит **до** `app.js`, но пользуется его помощниками (`$`, `LS`, `S`,
`openTopic`, `solvableParams`…). Поэтому на верхнем уровне в нём только
объявления функций и `let`; всё, что трогает `app.js`, вызывается из
`запуск()` (`подключитьПуть()`) или по нажатию. `app.js` зовёт его функции
через `typeof … === 'function'`: без `path.js` приложение работает как 1.9.

**Нижняя граница движка — ES2017 (Chrome 58, Safari 11; с указателями —
Safari 13).** Пособие ставят в обход магазина именно там, где магазина нет,
а вместе с ним нет и обновлений встроенного WebView. До 1.8.0 одна запись
`?.` в `app.js` делала весь скрипт неразборчивым на Chrome/WebView младше 80
и Safari младше 13.1, и пособие показывало картинку без единого слова. Что
нельзя: `?.`, `??`, спред в объектах (`Object.assign`), `catch` без
параметра, `flatMap`/`flat`, `.at()`, `replaceAll`, `Promise.finally`,
`Blob.text()` (есть `текстФайла()`), `ResizeObserver` без проверки,
`MediaQueryList.addEventListener` без запасного `addListener`. В стилях —
никакого `inset` (там сцена, телефонная сцена, настройки, диалоги), а у
каждого объявления с `color-mix`, `min()`, `max()`, `clamp()`, `dvh` — запасное
объявление того же свойства перед ним. Сторож в `index.html` написан на ES5.
Всё это проверяет `tests/compat.js` (разбор acorn из `tests/vendor/`) —
первым шагом `npm test`.

## Контракт симуляции

Каждая симуляция — запись в реестре `SIMS` (объявлен в `core.js`):

```js
SIMS.id = {
  title,
  params: [ {key,label,unit,min,max,step,default}
          | {key,label,type:'check',default}
          | {key,label,type:'select',options:[{v,t}],default}
          | {key,type:'group',label} ],          // визуальный разделитель
  init(p) -> state,                              // state.t — время, обязательно
  step(s, dt, p),                                // s.__stop='текст' → таймер встаёт
  draw(ctx, s, view, p),                         // мировые координаты, y вверх
  fit(p, {W,H}) -> {x,y,scale},                  // стартовый вид
  // необязательные расширения:
  graphs, presets, ctxTools, makeOutput, undoAction, …
  schema, timeless, timeUnit                     // timeUnit: 'нс', 'мс' — чем считать секунду сцены
}
```

Запись графика — `{label, unit, series?, get(s,p) -> [ряд0, ряд1|null]}`.
Необязательная пометка `наклон: i` говорит, что этот график — производная
графика `i` по времени, `знак: -1` — что со знаком минус (`ЭДС = −dΦ/dt`).
По ней разбор графиков сверяет касательную и площадь (см. «Производная и
интеграл на графиках»). Ставится руками и только там, где связь точная:
у орбиты единицы `r(t)` и `v(t)` подходят, но `v ≠ dr/dt`.

Параметр или группа может нести условие `если: p => …` — поле или вся
группа видны, только когда оно истинно (`видноПараметр()`). Так «Тело 2» и
«Тело 3» у «Второго закона» зависят от числа тел `n`, а у кинематики — от
`bodies`; у затухания группы «Свободные колебания» и «Вынужденная сила» — от
режима опыта. До 2.0.0 здесь было зашито `label==='Тело 2' && bodies!=='2'`,
и у «Второго закона», где поля `bodies` нет, второе тело не показывалось
никогда. `commit()` сравнивает видимость до и после и, если она поменялась,
перестраивает панель, возвращая курсор в то же поле.

`view` (объект `VIEW` из `app.js`) даёт симуляциям утилиты рисования:
`view.label(...)` — подписи, `view.c('--var')` — цвета из CSS-темы,
`view.lw(px)` — толщины линий с учётом зума.

Состояние выполнения (`RT[id]`) создаётся лениво в `rt(id)`: параметры,
state, вид, история Undo/Redo, пометки инструментами.

## Учебный контент (`js/topics.js`)

Тема: `{id, ch, title, why, key:[…], explore:[{sim, do, see}], needs:[id],
time, theory (HTML), derivations:[{goal, from:[…], steps:[{tex, why, op:[…]}], sim?}],
formulas:[{tex, kind, note, sim?}], examples:[{task, method, steps, answer,
check, sim?}], mistakes:[{wrong, right, why}], checks:[{q, a}],
links:[{to, text}],
problems:[{level, statement, sim?, answer(params), unit, hint?}]}`.
Темы группируются в `SECTIONS` (раздел может быть помечен `hard` — повышенная
сложность), «плоский» список — `ALL`. Ответы задач считаются от текущих
параметров привязанной симуляции — условия «живые».

**Пособие — повторение, а не курс с нуля.** Порядок блоков в `renderPane()`
задан именно этим: `why` (зачем тема) → `explore` (что покрутить в модели) →
`key` (пять пунктов, которые надо помнить) → `needs` (предпосылки) →
свёрнутый `theory` → `derivations` → формулы → пример → ошибки → вопросы →
связи. Симуляция стоит раньше текста намеренно: полный конспект открывается
кнопкой «Подробный разбор» и по умолчанию свёрнут везде, где есть `key`.

- `explore` — по три действия «сделайте / увидите» со ссылкой на симуляцию;
  кнопка открывает её сразу. Рендерится `exploreHTML()`.
- `needs` — id тем-предпосылок. Блок показывает чипы и до трёх вопросов из их
  `checks`; тему это не запирает. Рендерится `needsHTML()`.
- `derivations` — вывод формулы по шагам: `goal` обязан совпадать с одной из
  `formulas` темы (сверяются куски по разные стороны `=`), у каждого шага есть
  и формула, и обоснование. Шаги раскрываются по одному. Рендерится
  `derivHTML()`.
- `op` у шага — какими приёмами он сделан: имена статей из `js/ops.js`
  (см. «Приёмы выводов» ниже). Обязателен у каждого шага.
- `kind` у формулы — `закон` | `определение` | `следствие`; показывается
  значком рядом с формулой, чтобы выведенное не путали с принятым.
- `checks` — «Проверьте себя»: вопрос и ответ под кнопкой. Эти же вопросы
  переиспользуются в блоке `needs` тем, которые ссылаются на эту.
- `mistakes` — блок «Типичные ошибки»: неверная мысль, верная и объяснение,
  откуда берётся соблазн. Рендерится `mistakesHTML()`.
- `links` — сквозные связи между главами; `to` обязан быть существующим `id`
  темы, кнопка открывает её через `openTopic()`. Рендерится `linksHTML()`.

Целостность этих полей проверяется `npm run curriculum`: граф предпосылок без
циклов и битых ссылок, предпосылка стоит в оглавлении раньше темы, у вывода
есть цель-формула и шаги с обоснованиями, у каждого шага назван приём.

**Приёмы выводов (`js/ops.js`).** Раздела «Математика» в пособии нет: он был
(тригонометрия и векторы) и убран целиком перед 1.3.0 — глава о математике стоит
сбоку от физики, и в неё не заходят. С 1.7.0 математика живёт там, где ею
пользуются, — внутри шага вывода. У каждого из 306 шагов есть `op`: список
приёмов, которыми он сделан (подстановка, разложение по осям, малый угол,
интеграл как сумма, проверка крайними случаями — всего 40). Под шагом они
стоят метками; метка открывает карточку: что это за приём, когда он законен,
где ломается (с посчитанными числами — например, ошибка приближения малого
угла при 10°, 20°, 30°), и все другие выводы курса, сделанные тем же приёмом.
Переход из карточки открывает тему, раскрывает вывод до нужного шага и
подсвечивает его (`кШагуВывода()`).

`ПРИЁМЫ` — объект `{id: {группа, кратко, имя, что, законно, ломается,
подписи?}}`, `ГРУППЫ_ПРИЁМОВ` — порядок групп в справочнике. Особая метка —
`физика`: шаг, где в вывод входит закон, определение, опытный факт или
допущение модели, то есть то, что из предыдущих шагов не следует. Её
карточка вместо списка выводов говорит, в каких шагах текущего вывода
физика входит, — остальное преобразования.

Где что лежит в `app.js`: `чипыПриёмов()` рисует метки, `приёмHTML()` —
карточку, `разместитьПриём()` ставит её у метки (под ней, над ней или сбоку,
но никогда поверх самой метки; на телефоне — нижний лист), `гдеПриём()`
один раз строит указатель «приём → шаги». Полный список — четвёртая вкладка
«Справочника» в настройках; приёмы ищутся и в командной палитре.

`npm run curriculum` требует: у каждого шага непустой `op`, каждое имя есть
в `ПРИЁМЫ`, у каждой статьи заполнены все поля и есть хотя бы один шаг.
Последнее важно: статья без шагов — первый шаг к тому, чтобы справочник
расползся в отдельный курс математики. Метка не длиннее 22 знаков — она
стоит в узкой колонке телефона. Статьи проходят те же проверки сборки, что
и `topics.js`: удвоенный обратный слеш и `&lt;` вместо `<` внутри `$…$`.

**Задачи.** По пять на каждую симуляцию: `level` 1 — знакомство с моделью,
2–4 — средние, 5 — олимпиадная. Во вкладке «Задачи» они сгруппированы по
`sim`, заголовок группы открывает нужную симуляцию.

Правила, которым подчиняются условия:

- `answer(params)` получает **текущие** параметры привязанной симуляции,
  поэтому в условии не пишут чисел («при заданной начальной скорости»,
  а не «при 20 м/с»): у каждого ученика ответ свой;
- спрашивать то, что уже выведено в панели показаний, нельзя — иначе задача
  решается чтением. Проверяется скриптом `audit-readable2.js`: он считает
  ответ и все показания на каждом пресете и ловит величины, совпадающие
  **на всех** наборах параметров (разовое совпадение чисел — случайность);
- если при данных параметрах события не бывает (переправа без сноса при
  $u>v$), `answer` возвращает `NaN`/`Infinity` — приложение показывает
  «при этих параметрах события нет»;
- единицы ответа выбираются человеческие (мкН, нс, ×10³ км), чтобы не
  приходилось вводить `6.259e-11`.

Решённые задачи запоминаются в `S.solved` (persist через `LS`), над списком идёт
полоса прогресса, у каждой группы — счётчик `решено/всего`.

**Ключ отметки — имя задачи, а не её место.** Ключом служило `тема#индекс`,
то есть порядковый номер в массиве `problems`. Массив живой: задачи в главы
дописывают и вставляют между уже существующими. Вставка в середину сдвигала
все последующие, и чужие галочки переезжали на соседние задачи — человек
открывал главу и видел решённым то, чего не решал. Теперь ключ считает
`идЗадачи(тема, задача)` из `core.js`: это `задача.id`, если он задан явно,
иначе `тема.id + '#' + хэш(условие)` — FNV-1a по тексту условия без разметки.
Имя держится за смысл задачи, а не за её место, и переживает любую вставку.
Уникальность имён и их неизменность от выпуска к выпуску проверяет
`npm run curriculum` по снимку `docs/problem-ids.json`; осознанную правку
условия узаконивают `npm run curriculum -- --обновить`.

Прогресс, записанный прежними версиями, переводится один раз: IIFE в конце
`topics.js` прогоняет сохранённое через `перевестиОтметки()` и ставит
`physim.solvedSchema = '2'`, чтобы не делать этого дважды. Тем же переводом
проходит загрузка архива из настроек — иначе файл, выгруженный старой
версией, расставил бы галочки мимо. Ключ, который не удалось опознать,
остаётся как был: лишняя отметка лучше потерянной.

**Экранирование контента.** Символ `<` внутри `$…$` браузер принимает за начало
тега и проглатывает ближайший закрывающий — однажды из-за этого половина главы
уехала внутрь `.callout` и стала серой. Ошибку не видит ни проверка синтаксиса,
ни тесты физики, поэтому обе сборки вызывают `checkContentEscaping()` и падают
с понятным сообщением. В контенте пишите `&lt;` — KaTeX получит `<` обратно
из текстового узла.

**Итоги разделов.** Объект `RECAPS` в конце `topics.js` задаёт для раздела
`{theory, threads:[{title,text}], quiz:[{q,a}], links}`. Цикл после `SECTIONS`
дописывает в каждый раздел псевдо-тему `{kind:'recap', secId}`, которая
попадает в дерево наравне с обычными и рисуется отдельной веткой
`renderRecap()`: главное, сквозные идеи, качественные вопросы с раскрытием
ответа и лист всех формул раздела. Задач в сводке нет намеренно — проверяется
понимание, а не арифметика.

Формулы и вставки `$…$` во всех этих полях проходят через KaTeX, поэтому
внутри шаблонных строк обратный слеш нужно удваивать (`\\dfrac`): одиночный
JS съедает ещё до рендера.

## Раскладка: колонки и лист

**Компьютер.** Пристыкованные колонки: рельс инструментов, дерево тем,
конспект, разделитель, панель симуляции (шапка, сцена, шкала времени,
параметры и графики), снизу строка состояния. Ширины тянутся разделителем,
`H` убирает сцену и отдаёт страницу тексту, `F` разворачивает сцену.

В 1.4.0 эта раскладка была заменена «стендом»: сцена во всю страницу,
конспект полосой поверх неё, всё остальное — плавающие панели. В 1.4.1 стенд
убран и колонки возвращены: работать в нём оказалось неудобно. Телефонный
лист (ниже) при этом остался — там сцена и правда не должна уходить с экрана.

**Телефон** (`[data-ui="mobile"]`). Лист снизу с тремя положениями в
`data-detent` на `<html>`: `peek` (показания, перемотка, транспорт), `half`
(436 px — вкладка целиком), `full` (чтение, сцена сжимается в живую полосу
88 px). Лист **не накрывает** сцену: `.simpane` получает
`padding-bottom:var(--sheet)`, и после каждой смены положения вызывается
`resize()` + `fitView()` — то, что было видно, обязано остаться видимым.

Высота листа в положении `peek` не задана числом, а считается как
`var(--sheet-head) + var(--foot)`: строка транспорта на разных телефонах
разной высоты, и `--foot` меряется в `syncSheet()`.

Тело листа — либо `#simbottom` (параметры), либо `#content` (конспект или
задачи); переключает вкладка в `#msheet-tabs`. Оба элемента остаются на своих
местах в DOM и позиционируются в коробку листа стилями — перенос `<main>`
между родителями ломал бы обработчики и раскладку компьютера.

**`data-sim` на `<html>` обязателен.** `#content` играет две роли: вкладка
листа, когда сцена открыта, и самостоятельный экран чтения, когда её нет.
Правила листа были написаны без этой оговорки и прятали конспект в положении
«край» — то есть по умолчанию и всегда без симуляции. На телефоне читать было
нечего, хотя текст исправно рендерился: элемент стоял `display:none`. Поэтому
всякое правило листа, трогающее `.content` или `.chead`, обязано начинаться с
`[data-sim="on"]`, а `syncSheet()` — выставлять атрибут и снимать инлайновый
`display`, который ставила вкладка «параметры».

**У вкладки своё положение листа.** Параметры открываются на половине: их
крутят ради сцены, и сцену надо видеть. Чтение — на полном: на половине под
текст оставалось 158 пикселей, три строки. В полном положении транспорт и
перемотка убираются (их место — 150 пикселей — отдаётся тексту), а пуск
переезжает на живую полосу (`#stripctl`).

**Сцена-полоска.** При высоте сцены меньше `ПОЛОСКА` (140 px) подписи, числа
осей и надпись «сетка N м» не рисуются: они рассчитаны на полноразмерную
сцену и в полосе 88 px наезжают друг на друга. Настройка «без чисел» при этом
не трогается — проверка `сценаПолоска()` идёт рядом с ней, а не вместо.

К состоянию приложения лист добавил ровно две вещи: положение (`detent`) и
вкладку (`sheetTab`). Всё остальное — тема, параметры, время, масштаб,
инструмент — уже было.

**Планшет** — это не третья раскладка, а две существующие, которые обязаны
переживать переход друг в друга: iPad стоя получает телефонную, боком —
компьютерную (порог — 900 px по ширине, `uiMode()`). Ломалось здесь трижды.

1. *Поворот.* Разделитель писал ширину сцены пикселями в `style`, и она
   переживала смену раскладки: инлайновый стиль перебивал телефонные правила
   — сцена в 740 px на экране 820. Теперь ширина — доля, она пишется в
   `style` только в компьютерной раскладке (`разложитьКолонки()` из
   `resize()`), а в телефонной `style` очищается. При смене раскладки
   закрывается всё временное прежней: меню, ящик тем, карточка приёма.
2. *Средняя ширина.* Колонки 280 + 470 px на экране 960–1180 оставляли
   конспекту 161–481 px. Теперь сцена — доля доступного места (по умолчанию
   42 %, не шире 470 px, после перетаскивания — доля человека, `LS
   simFrac`), конспекту всегда не меньше 360 px, а ниже 1200 px панель тем
   ложится поверх конспекта (класс `.mid` у `#app`) и закрывается после
   выбора темы. Двойной клик по разделителю возвращает долю по умолчанию.
3. *Палец.* `data-touch="1"` на `<html>`, когда указатель грубый. В
   компьютерной раскладке это увеличивает цели до 36–40 px, ручки
   разделителей до 14 px и показывает то, что открывалось наведением мыши.

## Вычислитель (`js/calc.js`)

Модуль без DOM, одна глобальная `ВЫЧ`. Проверяется целиком в Node
(`npm run calc`, входит в `npm test`).

**Величина** — `{v, d, g}`: значение в СИ, размерность (степени шести
основных единиц `[м, кг, с, А, К, моль]`; угол безразмерен) и производные по
источникам погрешности. Каждое `±` заводит новый источник, операции ведут
производные (прямой автоматический дифференциатор), итог — `σ = √Σ(gᵢσᵢ)²`.
Поэтому корреляции учитываются сами: `x − x` одной и той же величины даёт
`0 ± 0`, два независимых измерения — `±√2`. Запись результата — по правилам
записи измерений: погрешность одной значащей цифрой (двумя, если первая 1
или 2), значение до того же разряда, нули в конце значащие.

**Строка.** Единицы — кириллицей (`ЕД`, с приставками), латиница — постоянные
(`ПОСТ`), функции — `ФУНКЦИИ`. Пробел между числом и единицей связывает
сильнее деления: `72 км/ч` — это `72 км / ч`. `2,5 ± 0,1 м` читается как
`(2,5 ± 0,1) м`. Сложение разных размерностей, логарифм и тригонометрия от
размерного, перевод в единицу другой размерности — ошибки с объяснением.
`A = B` — проверка размерности. У ошибок записи есть место (`e.разбор`,
`e.поз`), его показывает панель.

**Формулы курса.** `изTeX()` разбирает то подмножество TeX, которым написан
курс: `\dfrac`, `\tfrac12` (цифры без скобок — два аргумента), корни,
степени, индексы, греческие буквы, функции (`\cos^2\theta` — степень
значения), `e^{…}` с буквами в показателе — экспонента, `\Delta x`, `\bar v`,
`\langle v^2\rangle`, `U(x)` — одна величина, а не `U·x`, единицы в `\text{эВ}`.
Буквы подряд — произведение, как в самом TeX. Строка режется на части по
`\qquad`, условия в скобках в конце срезаются, `±` даёт две формулы, цепочка
`A = B = C` — равенства `A = B` и `A = C`. Не разбираются — и честно
отказываются — векторы, интегралы, суммы, неравенства, реакции и
**производные**: `\dfrac{dx}{dt}` как произведение «сократилось» бы в `x/t`.
Разбирается 184 формулы из 253.

**Решение.** Если неизвестное входит один раз — `выразить()` обращает
действия по пути к нему, `упростить()` приводит запись к виду учебника
(`g = 4π²L/T²`), ответ проверяется подстановкой: уход из-под корня даёт
посторонний корень, и тогда «решения нет». Если дважды и больше — корни
ищутся численно (перебор по логарифмической сетке обоих знаков и деление
пополам), размерность неизвестного выводится из самой формулы: каждая
размерность записывается как `a + b·x`, а сложение требует равенства.
Погрешность численного корня — через неявную производную `−(∂F/∂y)/(∂F/∂x)`.

`tests/calc.mjs` решает каждую разобранную формулу относительно каждой её
величины при случайных значениях и подставляет ответ обратно — 920 случаев.

**Панель** (`app.js`, раздел «ВЫЧИСЛИТЕЛЬ») — справа поверх сцены, на
телефоне во весь экран; `Ctrl+E`, кнопка в шапке, «Ещё» в меню сцены,
палитра. Кнопка «решить» у формул конспекта открывает её с выбранной
формулой. Постоянные подставляются только там, где буква однозначна
(`постояннаяДля()`: `h` — Планк в квантах и высота в механике). Подсказка
«что за величина» — из таблицы `СИМВОЛЫ` справочника, сначала в разделе темы.

**Ответы задач с единицами** — `ВЫЧ.ответЗадачи()`: голое число — в единицах
задачи, как раньше; с единицами — переводится; не та размерность — отдельный
вердикт с подсказкой «не хватает множителя «м»», потому что это другая
ошибка, чем неверное число.

## Модель ученика (`js/learn.js`)

Чистая логика без DOM, одна глобальная `УЧ`; целиком проверяется в Node
(`npm run learn`, входит в `npm test`). Ничего не уходит с устройства:
журнал лежит в `localStorage` (`physim.journal`) и едет в файл вместе с
остальными данными.

**Журнал** — `{задачи, вопросы, навыки, тренажёр, темы, диагн}`. По задаче
хранятся последние 12 попыток `[время, верно, вид промаха, откуда, навык]`
и момент решения. Отметки «решено» из версий до 2.0.0 переносятся один раз,
как решённые три дня назад. Файл с другого устройства **сливается**
(`слитьЖурнал`): попытки объединяются по времени, из тренажёров берётся
более долгий.

**Освоение темы** (`освоениеТемы`) — сумма уровней решённых задач (у
диагностики вдвое) минус штраф за нерешённые с промахами, плюс самопроверка
(«знал» +0,6, «не знал» −0,3), делённая на 9 (или на сумму уровней темы, если
она меньше). Статус: `new` — ничего; `work` — есть попытки; `done` — освоение
≥ 0,67; `due` — освоена, но наступил срок; `stuck` — три свежих (14 дней)
промаха при низком освоении.

**Повторение** — у темы `{этап, след, послед}`; интервалы 2, 5, 12, 28, 60,
120 дней. Удача в срок двигает этап вперёд, провал в срок — на шаг назад и
возвращает тему через день.

**Граф.** `фронт` — не освоенные темы, у которых освоены все `needs`.
`блокеры(тема)` — неосвоенные предпосылки обходом в ширину, ближние
первыми; освоенная не раскрывается дальше.

**Диагностика** — 12 тем (`ТЕМЫ_ДИАГНОСТИКИ`), из каждой задача 2-го уровня
с симуляцией. `советДиагностики` выбирает первым провал без проваленных
предков — его можно чинить сразу.

**Веер ошибок** (`веерОшибок(pr, params, def, дано, ед)`) пересчитывает
ответ той же `answer` задачи с «испорченными» параметрами — только теми,
что `answer` действительно читает (ловушка Proxy): угол 90° − θ (sin/cos),
θ·180/π (калькулятор в радианах), значение без перевода к СИ (`ед` из
вычислителя; для «×10²⁴ кг» — забытый множитель), μ = 0, переключённый
флажок модели, перепутанные величины одной единицы. Затем — преобразования
самого числа: знак, 10^k, ×2 и ½, π и 2π, g = 10, квадрат и корень. Промах,
не меняющий ответа, отбрасывается; совпадение — в допуске задачи 1,5 %.
Каждый промах относится к **навыку** (`НАВЫКИ`: имя, суть, правило, приём
справочника, генератор упражнений). Пять верных упражнений подряд — навык
«починен», и старые промахи с ним больше не зовут в ремонт.

`tests/learn.mjs` воспроизводит промахи на всех 389 задачах и требует, чтобы
каждый был назван, верный ответ не назывался промахом никогда, а случайное
число получало объяснение реже чем в 10 % случаев.

## «Мой путь» (`js/path.js`)

Панель `#path` поверх всего (на телефоне — во весь экран), вкладки
**Сегодня · Карта · Диагностика · Навыки · От вопроса**. Карта — слои по
длине самой длинной цепочки предпосылок, SVG строится под ширину панели.
`карточкаЗадачи()` — самодостаточная задача: условие, «Дано» (числа от
`solvableParams` с зерном дня, ключи — из `answerParams`), поле ответа с
единицами, веер ошибок, «В симуляции» переносит числа в модель.

В обычную вкладку «Задачи» модель встроена тремя вызовами: проверка пишет
попытку (`отметитьПопытку`) и показывает разбор (`показатьВеер`), «Показать
ответ» у нерешённой засчитывается промахом. Под заголовком темы — полоса
освоения и её блокеры (`полосаТемы`), в дереве — метка-кружок, налитый на
долю освоения (`меткаТемы`). Самопроверка получает «Вы знали ответ?».

## Персонализация и отклик (2.0.0)

`data-palette` (бумага, мята, северная, полночь, контраст) перекрашивает
основу поверх `data-theme`, который остаётся светлым или тёмным тоном — на
нём держатся сотни правил. Акцент — из десяти образцов или свой цвет;
`-300/-700/-800` выводятся из него смешением (`смешать`), иначе у своего
акцента подписи оставались фиолетовыми. Скругления, шрифт интерфейса,
ширина колонки и межстрочие — CSS-переменные (`--radius`, `--ui-font`,
`--read-w`, `--lh`); тени, стиль кнопок, подписи, мера движения —
атрибуты (`data-shadows`, `data-btnstyle`, `data-labels`, `data-motion`).

Раздел **Главное** (`страницаГлавное`) — темы карточками, образцы акцента,
размер текста, сегменты. **Профили**: четыре готовых и свои (`physim.profiles`);
применение запоминает прежние настройки (`physim.prefsUndo`). **Код обмена**
`PHYSIM1:` + base64 от JSON изменённых настроек; при разборе принимаются
только известные ключи известных типов, числа зажимаются в диапазон.
Короткие списки вариантов (до четырёх, до 40 знаков вместе) рисуются
сегментами (`сегментами()`).

Отклик: `подключитьВолну()` — волна от точки нажатия внутри `.rpl`
(обрезается скруглением кнопки, не трогая её `overflow`);
`подключитьПодсказки()` — свой всплывающий `title` с клавишей в `<kbd>`;
`подключитьПодписи()` — текст у значков верхней панели (`data-label`).
Кривые и длительности — `--ease`, `--t1…t3`; `data-motion="calm"` гасит
анимации, оставляя смену цвета, `off` — всё.

## Разделы, шапка темы, главный экран (`js/home.js`, 2.1.0)

**Вид разделов.** `ВИД_РАЗДЕЛОВ` — у каждого раздела два оттенка (для
светлой и тёмной основы) и значок. Элемент получает класс `.sx` и
`style="--sec-l:…;--sec-d:…"` (`стильРаздела`), CSS выбирает `--sec` по теме.
Цвет раздела живёт рядом с акцентом, а не вместо него: акцент отмечает
активное, раздел — где вы. Используется в дереве, на карте «Моего пути»,
в шапке темы и на главной.

**Шапка темы** (`шапкаТемы`, из `openTopic`): полоса и значок раздела,
сводка — время чтения (слова темы / 170 в минуту), формулы, выводы,
задачи, симуляции. **Полоса чтения** и кнопка «наверх» (`подключитьЧтение`)
слушают прокрутку и панели, и всей колонки: на компьютере прокручивается
`#pane`, на телефоне — `#content`.

**Главный экран** `#home` лежит внутри `.body` (`z-index` 55: ниже меню и
панелей) поверх уже открытой темы — «Продолжить» и выбор раздела только
снимают его. Разделы ведут в первую неосвоенную тему. Настройка
«При запуске» (`startScreen`): главный экран или сразу тема. Кнопки,
показывающие список тем или сцену, уводят с главной.

## Шапка темы поверх текста (2.2.0)

В компьютерной раскладке `.chead` лежит **поверх** `#pane` (`position:absolute`),
а у панели сверху отступ ровно на высоту шапки (`мерятьШапку`: при прокрутке,
смене темы и через `ResizeObserver`, если он есть). Прокрутка вниз прячет шапку
классом `tuck` — это `translateY(-100%)`, поэтому текст не двигается. Первая
версия убирала шапку отрицательным `margin-top`: весь текст прыгал вверх на
её высоту, и открытая карточка приёма оставалась на месте, закрывая метку.
На телефоне шапка и так прокручивается вместе с текстом — там её не трогаем.
Настройка «Прятать шапку темы при чтении» (`headerTuck`).

**Верхняя панель.** Навигация словами (`.tnav`: Главная · Курс · Мой путь) и
строка поиска по курсу (`#btn-cmdk` — открывает палитру). Где вы сейчас — класс
`cur` (`обновитьНав`), а не `on`: `on` у «Курса» исторически значит «в боковой
панели дерево тем». **Режим чтения** (`режимЧтения`) запоминает, были ли
открыты сцена и список тем, и возвращает ровно их.

**Показания-слова.** Значение показания может быть строкой (фаза движения) —
панель и лист телефона выводят её как есть, а не `fmt()`.

## Строгий стиль (2.2.1)

Скругления — одна шкала: `--radius-sm` (4), `--radius` (5), `--radius-lg`
(`--radius` + 2). Все прежние «таблетки» (10–20 px) сведены к ней одним
проходом по стилям; круглыми остались только переключатель и круглые кнопки
телефона. `--ease-spring` приравнена к `--ease` (без перелёта), `--lift` — 0:
под курсором меняются граница и фон, а не положение. Значки разделов
монохромные, цвет раздела — только тонкая линия. Волна от нажатия выключена
по умолчанию. Всё это — последний блок `css/style.css`, поверх прежних правил.

## Выпуск 3.0.0: относительность, переменный ток, слои сцены, лаборатория

**Раздел `rel`** стоит между оптикой и квантовой физикой: квантовые темы уже
пользуются $E=\gamma mc^2$ и порогом $2mc^2$, и теперь у этих формул есть
фундамент. Номер темы — `20а`: у Орира отдельной главы нет, а «28» посреди
оглавления читалось бы как опечатка. По той же причине переменный ток — `16а`,
сразу после индукции.

Все три сцены СТО считаются в замкнутом виде, без интегратора: у равномерного
движения и у разгона постоянной силой ($p=Ft$, $x=(mc^2/F)(\gamma-1)$) решение
известно, накапливать ошибку негде. Световые часы идут в наносекундах
(`timeUnit:'нс'`): часы в шапке, шкала времени и подписи графиков пишут
единицу из симуляции. Разгон электрона идёт в настоящих секундах — поле в
милливольты на метр выбрано так, чтобы $mc/F$ было порядка секунды.
В вычислитель добавлен световой год (`св. год`) — ответы задач по диаграмме
Минковского даются в нём.

**RLC-контур** (`ac.js`) — установившийся режим по точным формулам; секунда
сцены — 10 мс (`SLOW`). Точки тока бегут по схеме со сдвигом, пропорциональным
прошедшему заряду, — поэтому они замирают и разворачиваются вместе с током.

**Слои сцены** (`js/scene.js`) ни одной симуляции не требуют правок: всё
берётся из контракта. `record()` зовёт `слоиЗапись()` — туда пишутся все
`anchors()` кадра; «телом» при рисовании считается та опорная точка, что
сместилась дальше всех (у одних сцен первой идёт опора, у других — тело).
`restart()` превращает текущий путь в призрак. `drawAll()` зовёт
`слоиКамера()` до `applyWorld()` и `слоиРисовать()` сразу после `draw()` —
в тех же мировых координатах, затем `легендаСил()` в экранных.

`VIEW.fbd()` красит силу по подписи (`видСилы()`: `mg`/`Fg` — тяжесть, `N` —
опора, `Fтр` — трение, `T` — натяжение, `F_A` — Архимед, `F` — приложенная) в
цвета `--f-*` из темы и запоминает первую диаграмму кадра: её масштаб
(метров сцены на ньютон) и даёт линейку в легенде. Подписи получили ореол —
обводку цветом холста, толщиной 3 px (`labelHalo`).

**Лаборатория** (`js/lab.js`). Чистые функции (`лабМНК`, `лабШум`,
`лабСПогр`) проверяет `tests/lab.mjs` без браузера. X — параметр, показание
или время; Y — показание. Параметр в серии выставляется точно (это ручка
прибора), показания получают нормальный разброс. Погрешности — стандартные
ошибки коэффициентов МНК; число записывается до разряда двух значащих цифр
погрешности.

**Доступность.** `--ink-3` поднят до 4,5 : 1 к холсту во всех палитрах. У холста
сцены `role="img"` и описание `#scene-desc` (название и шесть первых показаний,
раз в секунду). Вердикт задачи и всплывающие сообщения — живые области.
Кнопки-значки получают `aria-label` из `title` при запуске.

**Экономный режим.** `экономияЗамер()` получает fps раз в 0,8 с; три замера
подряд меньше 24 кадров во время прогона — один раз включаются
`quality:'low'`, `dprCap:1`, `graphEvery:12`, `motion:'off'`, и об этом говорит
сообщение. Флаг `ecoDone` в хранилище не даёт повторять: если человек вернул
качество сам, пособие с ним не спорит. Выключается настройкой `autoEco`.

## Выпуск 3.1.0: объём и квантовые сцены

**3D.** Сцена с `rotate3d:true` поворачивается протягиванием левой кнопкой или
пальцем (режим `rot3d` в обработчиках указателя); двигать вид — Shift, средняя
кнопка, два пальца. Ориентация хранится в виде (`a.view.rot = {yaw, pitch}`),
начальная — `def.rot0`. `VIEW.p3(rot, доп)` возвращает ортогональную проекцию
`(x, y, z) → [X, Y, глубина]`, z — вверх. Сейчас так устроены орбитали и
конический маятник; у маятника подписи сил берут настоящие величины
(`mag`, `resMag` в `VIEW.fbd`), потому что в проекции стрелки короче.

**Орбитали** (`orbital` в `quantum.js`). $\psi_{nlm}=R_{nl}Y_{lm}$, радиальная
часть — через обобщённые многочлены Лагерра, угловая — через присоединённые
функции Лежандра (действительные комбинации или с определённым $m$). Точки
облака разыгрываются точно: радиус — обращением накопленного $r^2R^2$ на сетке,
направление — отбором по $|Y|^2$. Облака кэшируются по $(n,l,m,\text{вид},N)$,
генератор с зерном — картина не мерцает. Проверки: $\langle r\rangle=
\tfrac12(3n^2-l(l+1))a_0$ и число радиальных узлов $n-l-1$ до $n=6$.

**hudAware.** Схемы во всю сцену открываются со свёрнутой панелью показаний
(состояние остальных симуляций не трогается), а если её развернуть —
«вписать в кадр» отводит рисунку место под ней (`видВКадре()`).

**VIEW.text** рисует текст ровно в точке, без раскладки подписей: для клеток
таблицы (периодическая система) раскладка вредна — символ съезжал в соседнюю
клетку.

**Случайность в сценах** (`quantum2.js`) — генератор с зерном в состоянии:
одни и те же настройки дают одну и ту же картину, а проверки физики могут
сверять статистику (Штерн — Герлах: $\cos^2(\theta/2)$ с допуском 4 %).

## Производная и интеграл на графиках

Графики на панели — не картинка: у холста `.gcv` есть `подключитьАнализ()`.
Касание ставит `анализ = {вид:'касательная', t1, g}`, протяжка дальше 6 px —
`{вид:'площадь', t1, t2, g}`. Время хранится абсолютным, поэтому пауза,
прореживание истории и сдвиг оси его не сбивают; `restart()` разбор снимает.

- `локально()` — значение и наклон многочленом через 5 ближайших точек
  истории (она пишется каждые 6 шагов, т. е. раз в 1/40 с). Центральная
  разность ошибается на (ωh)²/6 — на быстрых колебаниях проценты; пять точек
  дают сотые доли. Значение парного графика берётся тем же многочленом;
- `площадьВ()` — трапеции со знаком, края интерполируются `значениеВ()`;
- `рисоватьАнализ()` рисует касательную и заливку до оси на всех графиках
  сразу — видно, что один момент времени общий для всех;
- `обновитьРазбор()` пишет текст в `#g-an`. Для графика с парой (`наклон`)
  наклон переводится в единицы парного графика через вычислитель (градусы
  против рад/с) и сравнивается с его значением; площадь — с изменением
  исходной величины. Меньше 3 % — «совпадает»; знаменатель не меньше 5 %
  размаха графика, иначе у нуля 0,001 против 0,0012 было бы «20 %». На
  изломе (ЭДС рамки, входящей в поле, — ступенька) наклон по точкам
  неточен, и текст так и говорит. У графиков без пары
  показывается только наклон или площадь того, которого коснулись, в
  «единица/с» и «единица·с». Шум счёта (меньше 10⁻⁹ размаха графика)
  выводится нулём. Текст перерисовывается, только когда он изменился.

`tests/graphs.mjs` (без браузера, входит в `npm test`) проверяет каждую
пометку: график существует, число рядов сходится, `[i]/с = [j]` по
размерности, а на прогоне 4 с центральная разность графика `i` совпадает с
графиком `j` в среднем лучше 5 %. Перевёрнутый знак у ЭДС даёт 200 %.

## Компиляция графика

График на панели — лента, которую ведёт цикл отрисовки: начинается там, где
включили расчёт, пишется с частотой кадров, прореживается через `graphEvery` и
обрывается на паузе. Для отчёта такой график не годится: два запуска с теми же
параметрами дают разные картинки.

`собратьРяд(def, params, t0, t1, точек, дробь)` считает симуляцию заново от
`init(params)` шагом `DT/дробь` и снимает значения на равномерной сетке
времени. Между узлами сетки не интерполируем: у события (удар, падение)
состояние меняется скачком. `__stop` обрывает ряд и возвращается в `stop` —
на картинке это пунктир с подписью.

Рисование не знает, куда рисует: `холстовыйДвижок` и `svgДвижок` отвечают на
один набор вызовов (`rect`, `line`, `poly`, `text`), а `рисоватьГрафик()`
вызывает их. Иначе пришлось бы держать две копии одной разметки и чинить
отступы дважды. Поля вокруг поля построения заданы явно
(`M={l:82,r:34,t:56,b:60}`), диапазон по Y расширен на 8 % — кривая не
касается рамки, подписи осей не срезаются.

Точность ограничена интегратором симуляции. Замерено на пружинном маятнике
против `x = A·cos(ωt)`: 3,8·10⁻⁴ м при шаге 1/240, 2,4·10⁻⁵ вчетверо мельче,
1,5·10⁻⁶ в шестнадцать раз мельче — ошибка падает как квадрат шага. У
баллистики расхождение нулевое: её график считается по замкнутой формуле.
Обе проверки и повторяемость — в `tests/regress.js`.

## Развёртка по параметру

Компилятор гонит модель по времени. 37 симуляций из 77 объявлены `timeless`:
от времени у них не зависит ничего, `graphs` пуст, и диалог их отказывался
обслуживать. Зависимость там есть, просто не от времени.

`собратьРазвёртку(def, params, ключ, от, до, точек, тДо, дробь, какие, прогресс)`
кладёт по оси X параметр, по оси Y — показатель из `readouts()`. Каждая точка
— отдельный прогон: `init()` с подменённым параметром, при `тДо > 0` ещё и
интегрирование до этого момента. У безвременных интегрирования нет вовсе,
поэтому развёртка там мгновенная. Точки считаются кусками по 40 мс, как и ряд
по времени.

Ничего не пишется под каждую симуляцию: список по X строится из
`числовыеПараметры(def)`, список по Y — из `показателиСимуляции(def,params)`.
`режимыКомпиляции(a)` говорит, какие режимы доступны, и запрещённый пункт в
диалоге гасится. Компилировать умели 36 симуляций, теперь 73.

`рисоватьГрафик` берёт подпись оси X из `ряд.xlab`, а подпись под картинкой —
из `ряд.подпись`; `графикВКартинку` принимает свой список `графики`. Дальше
обе дороги общие: предел холста, SVG/PNG/JPEG, сохранение файла.

## Сохранение файлов

`<a download>` работает не везде, и там, где не работает, он молчит — ничего
не происходит, ошибки нет. Два таких места:

* **Android-обёртка.** WebView без `DownloadListener` не скачивает ни `blob:`,
  ни `data:`. Из-за этого в `.apk` не работали компиляция графика, снимок
  кадра, запись и выгрузка данных — все четыре сразу, и ни одна не сообщала
  об этом. Оболочка теперь даёт мост `PhySim.saveFile(имя, mime, base64)`:
  файл пишется из Java в «Загрузки» через `MediaStore` (Android 10+) либо в
  собственную папку приложения на внешней памяти (старее). **Разрешений не
  добавлено**: оба пути обходятся без них, а ноль разрешений у пакета дороже
  удобного пути.
* **Safari на iPhone** игнорирует `download` у blob-ссылки и открывает файл.
  Там спасает системный «Поделиться» (`navigator.share` с файлом).

`сохранитьФайл(имя, blob)` пробует по порядку: мост оболочки → «Поделиться» →
обычная ссылка → открыть в новой вкладке. Через него идут все выгрузки.

## Предел холста

Браузер не сообщает, что холст слишком велик: он молча рисует пустоту. На
телефоне предел заметно ниже, чем на компьютере (у iOS при малой памяти это
5 Мпикс). Четыре графика стопкой при удвоении дают 13,8 Мпикс и 53 МБ —
отсюда «компиляция не работает»: файл сохранялся пустым.

`графикВКартинку()` подбирает масштаб под площадь: сперва вдвое крупнее, не
влезло — один к одному, не влезло и это — ужимает картинку целиком. Предел:
16 Мпикс на компьютере, 6 при грубом указателе. Результат проверяется
`холстНеПустой()` по углу — там заведомо лежит фон.

Длинные промежутки считаются кусками по 40 мс (`собратьРядПостепенно`) с
показом прогресса: синхронная петля подвешивала вкладку, и на телефоне это
выглядело как «нажал — ничего не произошло».

## Ядро (`js/app.js`)

- **Состояние** `S` + persistence в `localStorage` через обёртку `LS`
  (ключи с префиксом `physim.`).
- **Холсты**: `#scene` (сцена) и `#overlay` (пометки/измерения) с учётом
  devicePixelRatio; рендер-цикл с фиксированным шагом физики `DT = 1/240 c`
  и множителем скорости времени.
- **UI**: дерево тем, конспект/задачи, панель параметров, графики, пресеты,
  полноэкранные настройки, горячие клавиши, запись WebM.
- **Прокрутка конспекта** зависит от вида. На компьютере крутится `.pane`,
  а `.chead` (название темы и вкладки) закреплён над ним. На телефоне та же
  плашка съедала около четверти экрана всё время чтения, поэтому там
  прокручивается весь `.content` — заголовок уезжает вверх как обычный
  абзац. Сбрасывать позицию поэтому нужно у обоих: `paneTop()`.
- **`syncBottomInset()` → `--mbot` и `MBOT`.** Плавающая панель на телефоне
  лежит поверх сцены, и её высота меняется (пилюля в один ряд или
  полноширинная строка в два). Всё, что пишется у нижнего края, поднимается
  на измеренную высоту: подсказки и плашка события — через CSS-переменную
  `--mbot`, мини-карта и название сцены на холсте — через `MBOT`. Меряем по
  `offsetTop`, а не по `getBoundingClientRect()`: панели переключаются с
  анимацией `transform`, и прямоугольник в момент вызова показывал панель
  ещё сдвинутой.
- **Свои диалоги** `askBox()` / `askConfirm()` / `askText()` вместо
  `prompt()` и `confirm()`. Системные диалоги в Android-WebView без
  `WebChromeClient` молча возвращают `null`/`false` — в `.apk` из-за этого не
  работали ни заметки на сцене, ни сохранение набора параметров, ни одно
  подтверждение. Свой диалог ведёт себя одинаково в браузере, в `.apk` и в
  `.exe`; обратный вызов, а не Promise, чтобы точки вызова остались простыми.
- **Режим окна** (`applyWindowMode()`, настройка `winMode`). Настоящее
  управление окном есть только у упаковки `.exe`: `packaging/windows/preload.js`
  отдаёт странице ровно одну функцию `physimShell.setWindowMode()`, а
  `main.js` по IPC переключает окно. В браузере управления окном нет —
  доступен только Fullscreen API, поэтому «в окне» и «весь экран в окне»
  там совпадают. При запуске полноэкранный режим не запрашивается: браузер
  всё равно отклонит его без действия пользователя (флаг `S.__ready`).
  `F11` (`cycleWindowMode()`) гоняет режимы по кругу; кольцо режимов зависит от
  оболочки: в `.exe` три режима, в браузере два — предлагать там «весь экран в
  окне» бессмысленно, он ничем не отличался бы от обычного полноэкранного.
- **Заставка** (`#splash` в `index.html`, `playIntro()` в конце `app.js`).
  Разметка лежит в HTML, а не создаётся скриптом, — чтобы появиться в первом
  же кадре и заодно работать индикатором загрузки. Анимация целиком на CSS,
  JS только добавляет класс `.go` (финал) и убирает элемент. Половины экрана
  непрозрачные и разъезжаются занавесом, поэтому «Phy» лежит в левой
  половине, а «Sim» — в правой: они уезжают вместе с ней. Есть страховка
  (CSS-анимация прячет заставку через 9 с, если скрипты не выполнились),
  пропуск касанием и настройка `intro`.
- **`fitFormulas()`** держит формулы в границах колонки. Выносные
  (`.katex-display`) ужимаются кеглем до ширины своего блока — за несколько
  проходов, потому что ужимаются они не строго пропорционально; ниже
  `0.68em` не опускаемся, такие прокручиваются сами в себе
  (`overflow-x:auto`). Строчные формулы шире колонки получают класс
  `.katex-scroll` — только те, что действительно не влезли, иначе
  `inline-block` сбивал бы короткие формулы с базовой линии. Ширину меряем
  у `.katex-html > .katex-base` (у самой `.katex` она уже ограничена
  колонкой) и **у каждой формулы по её собственному блоку** — внутри врезок
  колонка у́же. Вызывается трижды: сразу, следующим кадром и по
  `document.fonts.ready` — пока шрифты KaTeX не подгрузились, формула
  меряется подстановочным шрифтом и выходит процентов на шесть шире.
- **Ввод на сцене** — Pointer Events на `#cwrap`: панорама/рисование/захват
  точек одним указателем; зум колесом/тачпадом к курсору (`wheel`); зум
  двумя пальцами (пинч) на сенсоре — активные касания копятся в `Map`
  `touches`, при двух указателях включается режим `pinch`, который
  масштабирует к середине между пальцами и панорамирует её сдвигом (та же
  математика «держим мировую точку под курсором», что и у колеса). Работает
  благодаря `touch-action:none` на канвасе.
- **Раскладка**: десктоп — конспект и симуляция бок о бок со сплиттером;
  ≤900px — симуляция ложится поверх конспекта (`position:fixed`) и
  закрывается кнопкой «назад» (`#btn-simback`, показывается только в этом
  медиазапросе; управляется классами, не inline-стилями — см. историю бага
  в комментарии у правила `#btn-simback` в `css/style.css`).
- **Телефон** (≤900px) — раскладка по отдельному макету. Весь компьютерный UI
  (`.topbar`, `.statusbar`, `.rail`, вкладка «Конспект») скрыт, вместо него:
  - тонкая шапка `.mtop`: ящик тем слева, «открыть симуляцию» и «⋮» справа;
  - конспект показывается голым текстом — без заголовков-вкладок и хлебных
    крошек;
  - дерево тем — выезжающий слева ящик (`.sidebar.open` + `#drawer-bg`),
    закрывается тапом по затемнению и сам закрывается при выборе темы;
    в подвале ящика логотип, помощник и настройки;
  - плавающая панель `#mbar`: инструменты · шаг назад · пуск/пауза · шаг
    вперёд · параметры · «ещё». Кнопка «ещё» прячет основной ряд и открывает
    `#mbar2` (сброс, зум, вписать, скорость) — вернуться можно такой же
    кнопкой справа. Все кнопки **проксируют** на существующие обработчики;
  - параметры и графики — выезжающая снизу шторка (`.msheet-open`) с
    затемнением `#msheet-bg`;
  - инструменты сцены — попап `#pop-tools`, собираемый из кнопок левой панели
    (`fillToolsPop`), поэтому список не дублируется и не расходится;
  - жест: одним пальцем панорама/рисование, двумя — пинч-зум.

  **Как включается телефонный вид.** Не по ширине окна: узкое окно на
  компьютере — это всё ещё компьютер, и телефонные панели там только мешают
  (раньше `.mbar` вообще разворачивалась обычным блоком посреди сцены, потому
  что вне медиазапроса у неё не было ни одного правила). Решает `uiMode()`
  по СПОСОБУ ВВОДА: грубый указатель без наведения (палец) плюс узкий кадр,
  либо мобильный UA. Результат кладётся в `data-ui` на `<html>`, и вся
  телефонная раскладка в CSS висит на `[data-ui="mobile"]`. Настройка «Вид
  интерфейса» позволяет задать режим вручную.

  **Адресная строка браузера.** На телефоне сверху или снизу почти всегда
  висит панель браузера, и обычные `100vh` про неё не знают — в Safari они
  считаются по экрану БЕЗ панелей. Поэтому `syncViewport()` берёт размеры у
  `visualViewport` и выставляет две переменные: `--appvh` (высота приложения)
  и `--vvbottom` (сколько отъедено снизу — панель браузера или клавиатура).
  На `--vvbottom` приподнимается всё плавающее, поэтому панель управления
  никогда не оказывается под поисковой строкой. Обновляется на `resize`,
  `orientationchange` и событиях самого `visualViewport`.

## Служебный поток и версия (`sw.js`)

Сайт на GitHub Pages обслуживает `sw.js`: офлайн и установка «на главный
экран». Стратегия — «отдать из кэша, следом обновить» для файлов и «сначала
сеть» для самой страницы.

**Имя кэша несёт номер выпуска** (`physim-3.1.0`). Это не украшение. Пока имя
было постоянным, файлы обновлялись в кэше поодиночке: `index.html` — килобайты,
долетал первым; `app.js` — полмегабайта, часто не успевал. Достаточно закрыть
вкладку раньше, чем докачается всё, и следующее открытие получало СМЕСЬ
выпусков. Обработчики в `app.js` вешаются на верхнем уровне, поэтому одного
пропавшего элемента хватало на `TypeError` на первой же строке: страница
отрисована, приложение мертво. На `.apk` это не влияло никогда — там один
согласованный набор файлов и служебного потока нет вовсе.

Страница идёт «сначала сеть» (с ожиданием 2,5 с и откатом в кэш) по той же
причине: она решает, какой версии будут все остальные запросы этого открытия.

**Версия живёт в четырёх местах** — `package.json`, `sw.js`, метка
`<meta name="physim-build">` в `index.html` и `window.PHYSIM_BUILD` в конце
`app.js`. Проставляет её **сборка** (`проставитьВерсию()` в
`build-standalone.mjs`), а `npm test` сверяет: руками в четырёх файлах её
забыли бы ровно один раз.

**Сторож в странице.** `app.js` последней строкой ставит `PHYSIM_READY`. Если
через четыре секунды после загрузки отметки нет или номер выпуска в ней не
совпал с меткой в разметке, страница сносит кэш вместе со служебным потоком и
перезагружается — один раз за сеанс. Не помогло со второго раза — показывает
объяснение вместо мёртвого экрана. Это единственный способ починить браузер,
у которого смесь уже лежит в кэше.

**Терпимый поиск `$$`.** Обработчики на верхнем уровне вешаются через
`$$('#id')` (`core.js`): при отсутствии элемента возвращается заглушка, и
присваивание обработчика ни на что не влияет. Пропавшая кнопка стоит кнопки,
а не всего пособия.

## Сборка (`build-standalone.mjs`)

Приложение открытое: обфускации и пароля больше нет — раньше и то и другое
существовало, чтобы ученик не читал ответы к задачам прямо в исходнике.
Осталась одна сборка, `npm run build`: она склеивает `css/`, `js/` и KaTeX в
единственный файл `phy-sim-standalone.html` (шрифты — в `data:`-URI). Он нужен,
чтобы пособие можно было переслать одним файлом и открыть двойным кликом.

Список скриптов берётся **прямо из `index.html`** и в том же порядке: когда-то он
был выписан в сборке руками, и новый файл симуляций попадал в обычную версию, но
не в сборку — расхождение обнаруживалось только по числу симуляций.

Перед склейкой вызывается `checkContentEscaping()` и роняет сборку, если в
учебном контенте нашёлся неэкранированный `<` внутри `$…$` (см. ниже).

Упаковки `.apk` и `.exe` копируют исходники как есть — отдельной «раздаточной»
версии больше не существует.

## KaTeX (`vendor/katex/`)

Раньше KaTeX подключался с CDN, и без сети формулы показывались сырым
TeX-текстом — то есть в школьном классе без интернета и в упаковках `.apk`
и `.exe` конспект читался хуже всего. Теперь библиотека лежит в репозитории:

* `katex.min.js` + `auto-render.min.js` — рендер и поиск `$…$` в тексте;
* `katex.min.css` — правила `@font-face` переписаны на **только `woff2`**
  (296 КБ вместо 1,2 МБ: `woff` и `ttf` не нужны ни одному браузеру после 2015
  года, а лишние `url(...)` дали бы 404);
* `fonts/*.woff2` — 20 начертаний.

`build.mjs` копирует папку в `dist/` как есть (обфусцировать чужую библиотеку
незачем), `build-standalone.mjs` встраивает её вместе со шрифтами.

## Упаковка в приложения (`packaging/`)

`.apk` и `.exe` — тонкие оболочки вокруг той же `dist/`; отдельной версии кода
нет. Подробности и команды — в [../packaging/README.md](../packaging/README.md).

* **Android** (`packaging/android`) — `Activity` с `WebView`, который открывает
  `file:///android_asset/index.html`. `npm run build:apk` собирает `.apk`
  **без Android SDK**: `aapt2` берётся из `org.apktool:apktool-lib`,
  `android.jar` — из `org.robolectric:android-all`, дексер — из
  `com.jakewharton.android.repackaged:dalvik-dx`, подпись ставит `jarsigner`
  из JDK. Отсюда же `targetSdkVersion=29`: с 30 Android требует подпись
  схемы v2, а `apksigner` есть только в SDK.
* **Windows** (`packaging/windows`) — оболочка Electron, `electron-builder`
  делает NSIS-установщик и портативный `.exe`. Кросс-сборка с Linux работает,
  но требует Wine **и 32-битного тоже**: `rcedit` и NSIS — 32-битные, а
  64-битный Wine-префикс с ними несовместим (нужен отдельный `WINEARCH=win32`).

Аппаратная кнопка «назад» на Android обслуживается хуком `window.physimBack()`
в `app.js`: он закрывает верхний открытый слой (попап → палитра → справка →
настройки → шторка → ящик тем → сцена) и возвращает `false`, когда закрывать
нечего — тогда оболочка закрывает приложение. В браузере хук просто не
вызывается.

## Настройки (`PREFS` в `js/app.js`)

Каждый пункт — запись `{cat,key,type,def,name,desc,…}`; `type` — `toggle`,
`select` или `range`. Значения живут в `S.settings`, дефолты — в
`PREF_DEFAULTS`, отрисовка полностью автоматическая (`prefRow`/`renderPrefs`),
поэтому новый пункт добавляется одной записью в массив.

Важно: добавив запись, надо **подключить** ключ к поведению — иначе получится
мёртвый переключатель. Места подключения: `applySettings()` (тема, плотность,
CSS-хуки `data-serif`/`data-dock`/`data-hudside`/`--hudk`), `drawGrid`/`gridStep`
(сетка), `fmt` (точность чисел), `loop`/`resize` (кадры, DPR, плотность точек
графиков), `stopEvent` (пауза на событиях), обработчики зума и `toast`.
Проверить, что мёртвых пунктов нет, можно поиском использований ключа вне
объявления `PREFS`.

## Инструменты сцены

Левая панель (`#rail`) разбита на сворачиваемые папки (`.railgrp`, состояние в
`LS` под ключом `railGroups`): навигация, **классические инструменты**,
**инструменты раздела** и **конструкторы**.

Левая панель содержит инструменты, общие для всех разделов.
Большинство создаёт **пометки** — записи в `a.annos`, которые рисуются в слое
`#overlay` и отменяются через `Ctrl+Z` (`annSnapshot`/`annUndo`):

| Тип пометки | Инструмент | Что показывает |
|---|---|---|
| `pencil` | карандаш | произвольная кривая (свой цвет и толщина) |
| `ruler` | линейка | расстояние; настройками — стрелка (бывший вектор), выноски (бывшая размерная линия), угол к горизонтали, единица и точность |
| `circle` | окружность | радиус и площадь круга |
| `area` | площадь | площадь и периметр многоугольника (формула шнурования) |

**Былые типы пометок.** `vector`, `dim`, `angle`, `guide` и `note` описаны в
`TOOL_STYLE` с признаком `былое:true`: инструментов с такими именами в стойке
нет, но пометки этих типов рисуются как прежде — иначе рисунки, сделанные
предыдущими версиями, открывались бы искажёнными. `РИСУЮЩИЕ` собирается из
`TOOL_STYLE` без них, и полоса настроек им тоже не показывается.

Вектор и размерная линия сведены в линейку: `вектором()` и
`линейкаСВыносками()` (клавиши `Y` и `D`) включают её в нужном оформлении.
Транспортир и направляющая убраны целиком. Заметка стала карточкой (см.
ниже) и пометкой на холсте больше не является.

При выборе любого рисующего инструмента раскрывается полоса `#penbar`
(`renderToolbar()`). В самой полосе — только то, что меняют по ходу рисования:
кружок цвета (открывает круговую палитру `#pop-color`), три последних цвета,
толщина числом, тип линии и ползунок прозрачности. Всё остальное уходит в
«⋯» (`#pop-toolmore`) строками с подписями: со всеми настройками сразу полоса
разрасталась до 957 пикселей против 470-пиксельной сцены. На телефоне в «⋯»
уезжает и тип линии — там на полосу 368 пикселей.

Цвет хранится либо именем переменной темы (`--danger`), либо кодом
(`#7c3aed`): первое следует за сменой темы, второе — нет, и это осознанно.
Круг рисуется попиксельно (`рисоватьКруг`): оттенок по углу, насыщенность по
радиусу, яркость ползунком.

Толщина вводится в пикселях, а хранится прежним множителем `k` к базовой
толщине инструмента — поэтому вид старых пометок не изменился.

Что показывать — объявлено в `TOOL_STYLE[tool].opts`, и список у инструментов
разный, потому что каждый пункт действительно меняет отрисовку:

| `opt` | что настраивает | у кого |
|---|---|---|
| `line` | сплошная / пунктир / точки (`dashOf`) | у всех, кроме заметки |
| `alpha` | плотность: 1 / 0.65 / 0.35 | у всех |
| `arrow` | стрелки: на конце / с обеих сторон / без | вектор |
| `fill` | заливка фигуры | окружность, площадь |
| `ext` | выноски как на чертеже | линейка |
| `size` | кегль подписи | (былое) |
| `ang` | угол к горизонтали | линейка |
| `unit` | единица: км / м / мм / нм | линейка |
| `dec` | знаков после запятой, 0…3 | линейка |
| `label` | показывать ли число | измерительные |

Кнопка `⟲` убирает запись инструмента из `S.tstyle` — он возвращается к
объявленному виду. Настройка своя у каждого инструмента (`S.tstyle`,
`LS`-ключ `tstyle`) и **копируется в саму пометку** в момент создания
(`markStyle()`), а не читается при отрисовке, — иначе смена цвета
перекрашивала бы всё нарисованное раньше. Толщина хранится множителем к
базовой толщине инструмента: у линейки и карандаша разная привычная толщина,
а «жирно» должно быть одинаково жирным для обоих; множитель 1 означает «как
было всегда», поэтому вид старых пометок не изменился.

Полоса стоит **внизу** сцены на компьютере и **вверху** на телефоне: у
каждой раскладки свободен свой край. Вверху на компьютере живут плавающие
панели, и полоса накрывала шапку «Показателей» — панель нельзя было схватить,
пока выбран инструмент.

Отдельная тонкость: жест на холсте начинается только если нажали **по самой
сцене** (`e.target!==scene` в обработчике `#cwrap`). Внутри обёртки лежит и
весь плавающий интерфейс, а обработчик вызывал `setPointerCapture` на
`#cwrap` при нажатии по чему угодно: указатель уводился с кнопки, `pointerup`
приходил уже на `#cwrap`, и события `click` не возникало вовсе.

**Выделение** (`select`) — инструмент без пометок: клик выбирает пометку под
курсором, протяг по пустому месту обводит рамкой, протяг по выбранному
переносит группу, `Delete` удаляет, `Escape` снимает выбор. Номера выбранного
лежат в `S.sel` и сбрасываются при смене инструмента, симуляции и откате —
после них индексы в `annos` уже не те. Попадание, габарит и перенос вынесены в
`попалВПометку()`, `габаритПометки()` и `сдвинутьПометку()`; ими же пользуется
резинка, поэтому «попал» для выбора и для стирания означает одно и то же.

**Shift и Alt при рисовании.** У рисующих инструментов `Shift` больше не
панорамирует (`РИСУЮЩИЕ` в обработчике `pointerdown`), а держит направление
0°/45°/90° — `подРавнение()` считает по мировым координатам, поэтому угол
на экране получается тот же. Панорама остаётся на средней и правой кнопках.
`Alt` + клик стирает пометку под курсором, не заставляя переключаться на
резинку.

Площадь (`area`) копит вершины между кликами, поэтому `pointerup` **не**
сбрасывает для неё `a.draft`; набор завершается двойным кликом или `Enter`,
отменяется `Escape`.

## Заметки-карточки

Заметка перестала быть пометкой на холсте: она жила в мировых координатах,
уезжала вместе со сценой, правилась через диалог и стиралась случайным мазком
резинки. Теперь это DOM-карточка в `#notelayer` поверх сцены — в ЭКРАННЫХ
координатах, как плавающие панели.

Хранится в `a.notes` (не в `annos`, поэтому резинка её не видит вовсе):
`{id, x, y, w, h, title, text, open, tucked, links:[id], показ}`. Положение
`x`/`y` — доля от размера сцены, а не пиксели: иначе при смене размера окна
или повороте телефона карточки оказывались бы за краем. Автосохранение — в
`LS` под ключом `notes`, по симуляции; в файл и обратно — из меню сцены,
вкладка «Данные» (при загрузке идентификаторы перевыдаются, иначе связи
склеились бы с уже лежащими карточками).

Разметка тела: `#` — строка чуть крупнее, `##` — совсем крупная. Порядок
обратный обычному маркдауну и задан намеренно; подсказка в редакторе говорит
об этом прямо.

Связи рисуются `<svg id="notelinks">` ПОД карточками, от края до края
прямоугольников (`рисоватьСвязи`), пунктиром и вполсилы — линия не ложится ни
на текст, ни на сцену. Связанные читаются не уходя с карточки: полоска снизу
подменяет содержимое (`n.показ`), «← назад» возвращает.

`renderNotes()` пересобирает слой целиком, в том числе на каждом пересчёте
раскладки. Поэтому он запоминает, в каком поле и на каком символе стоял
курсор, и возвращает его после сборки: иначе набранное посреди слова молча
пропадало.

**Инструменты раздела** (`SECT_TOOLS`, папка `#secttools`) — не пометки поверх
картинки, а вмешательство в саму физику сцены: невесомость, трение, затухание,
нагрев/охлаждение, поршень, удвоение поля, обращение полярности. Каждый
инструмент объявляет НАБОР КЛЮЧЕЙ параметров и показывается только там, где
такие параметры есть, а границы берёт из описания самого параметра
(`paramDef`/`clampParam`). Поэтому список «инструмент → симуляция» вести не
надо: механика сама получает невесомость, термодинамика — нагрев, оптика —
длину волны. Подписи универсальных кнопок («удвоить») собираются из `label`
самого параметра, поэтому в линзе это фокусное расстояние, а в эффекте
Доплера — частота сирены. Каждое нажатие проходит через `pushUndo`, так что
откатывается `Ctrl+Z`.

**Инструменты конкретной симуляции.** Симуляция может объявить `ctxTools(p)` —
раньше они были доступны только в меню по правой кнопке (на телефоне туда не
попасть). Теперь `renderSimTools()` рисует их кнопками в той же левой панели
(`#simtools`), а правая кнопка продолжает работать как раньше.

## Заметки: правка и восстановление (2.2.0)

Правка карточки кончается, когда фокус ушёл из **карточки**, а не из поля
текста (`focusout` с `relatedTarget` и отметкой нажатия внутри). Плюс
перехват `pointerdown` на документе: нажатие мимо карточки закрывает правку,
даже если фокус к тому моменту уже ушёл — например, в диалог «удалить?».
Текст сохраняется по ходу набора с паузой 600 мс. Состояние экрана (`edit`,
`показ`) в хранилище не пишется. Ярлычок возвращается касанием (перенос без
сдвига = нажатие). Карточка всегда целиком в пределах сцены: левый верхний
угол зажат в `[0, W − ширина] × [0, H − высота]`. Заметки из хранилища и из
файла проходят `чистаяЗаметка`: числа — числа, строки — строки, ссылки —
только строки-идентификаторы.

## Раскладка подписей на сцене

Симуляции ставят подписи вручную пиксельными сдвигами, поэтому на разных зумах
они наезжали друг на друга и уходили за кадр. Раскладка чинится централизованно
в `VIEW.label()`: длинная строка ужимается по кеглю (11→8 px), затем подпись
прижимается внутрь кадра, затем — если она перекрыла уже нарисованную —
сдвигается по вертикали до свободного места. Занятые прямоугольники копятся в
`VIEW._lbl` и обнуляются каждый кадр вызовом `VIEW.labelFrame()` в начале
`drawAll()`. Отключается настройкой «Разводить подписи на сцене».

## Плавающие панели

Показания, энергия, PV-диаграмма, гистограмма и сравнение снимков живут внутри
`#cwrap` как «окна»: общий класс `.fpanel`, шапка `.fp-head` (перетаскивание) и
уголок `.fp-grip` (изменение размера). Список панелей — `FPANELS` в `app.js`;
`makeFloating(el)` навешивает поведение на любую из них, `fpSave()/fpLoad()`
держат положение и размер в `LS` (ключ `physim.panels`), двойной клик по шапке
сворачивает панель (`.rolled`), `resetPanels()` возвращает раскладку по
умолчанию. Панель, которую пользователь не трогал, продолжает вставать на своё
место из CSS, поэтому старые раскладки не ломаются.

## Обвязка сцены

`drawSceneChrome()` рисует пять необязательных слоёв в ЭКРАННЫХ координатах на
слое пометок, каждый со своим выключателем в настройках: оси координат,
линейки по краям кадра, перекрестие курсора, мини-карта (вся сцена + рамка
видимой области) и название сцены. Положение курсора для перекрестия и для
всплывающих ручек перетаскивания берётся из `S.ptr`, который обновляется на
каждом `pointermove` независимо от режима «координаты под курсором».

## Меню сцены (`#pop-simmenu`)

Открывается тремя точками в шапке сцены и правой кнопкой по сцене
(`openSimMenu()`). Команд накопилось одиннадцать, подряд они читались как
свалка, поэтому разложены по вкладкам `МЕНЮ_ВКЛАДКИ`: **Сцена** (снимок,
запись, вписать вид, убрать пометки, полный сброс), **Данные** (компиляция
графика, снимок показаний, копирование показаний), **Конструктор**,
**Наборы** (сохранённые параметры), **Ещё** (палитра, контрольная, клавиши,
настройки). Вкладка «Конструктор» добавляется, только если симуляция
объявляет `ctxTools`.

Выбранная вкладка помнится отдельно для обычной сцены и для конструктора
(`менюВкладка`): в конструктор заходят за деталями, на обычную сцену — за
снимком, и подставлять одно вместо другого было бы навязчиво.

Содержимое собирает `собратьМенюСцены()`, и звать её обязан **каждый** путь
открытия. Путей четыре: `openSimMenu()` (правая кнопка) и три кнопки через
общий `popup()` — в шапке сцены и две на телефоне. `popup()` только снимает
класс `hidden`, поэтому меню, открытое кнопкой, оставалось с пустой полосой
вкладок и одной видимой страницей «Сцена»: остальные лежат в разметке
скрытыми и ждут `setMenuTab()`.

**Слои на телефоне.** Обвязка закреплена у корня страницы: `#mbar` 124,
`#stripctl` 128, `#msheet` 126, `#timeline` 127. Экран во весь экран обязан
лежать выше неё — `.prefs` 140, ящик тем 141 с затемнением 140. Внутри
`#simpane` (70) свои слои считаются от него и потому безопасны; ошибиться
легко именно на панелях, закреплённых у корня.

## Параметры: группы

`renderParams()` кладёт поля не плоским списком, а в тело своей группы
(`.pgroup > .pg-h + .pg-b`). Группа складывается щелчком по заголовку,
состояние помнится по паре «симуляция + название группы» (`LS`-ключ
`pgroups`). По умолчанию сворачиваются группы с третьей и дальше — и только
у симуляций, где полей больше двенадцати (у `newton2` их 27). На заголовке
стоит счётчик: сколько полей внутри и сколько уже уведено от исходного
значения, — иначе свёрнутая группа прятала бы правки молча. Фильтр
(`applyParamFilter()`) раскрывает группы с совпадениями классом `found`,
чтобы найденное не оставалось в свёрнутой.

## Кастомизация окружения

Оформление сцены задаётся настройками и живёт на корневом элементе:
`data-bg` (подложка: сплошная, тетрадь, миллиметровка, точки, тёмная),
`data-rail` (сторона панели инструментов), CSS-переменная `--panel-a`
(непрозрачность плавающих панелей). Насыщенность сетки читает `drawGrid`,
шрифт и кегль подписей — `sceneFont()` внутри `VIEW.label`, размер
наконечников — `VIEW.arrow`.

## Командная палитра

`Ctrl+P` (и кнопка в шапке) открывает единый поиск по темам, симуляциям,
настройкам и командам — `Ctrl+Shift+P` или префикс `>` оставляет только
команды. Источник строится в `cmdkSource()`; поиск нечёткий (сначала точное
вхождение, затем совпадение букв по порядку). Список команд — `CMDS`,
добавление новой команды = одна запись в массиве.

## Шкала времени

`record()` пишет не только точки графиков, но и ленту снимков состояния
(`a.tape`, снимок не чаще чем раз в 0.02 с модельного времени, до 900 кадров).
Ползунок `#tl-range` переводит расчёт в режим просмотра (`S.scrub` — индекс
кадра): состояние берётся из ленты, физика на это время встаёт, кнопка «живой
расчёт» возвращает последнее рассчитанное состояние. Зацикливание (`S.loop`)
перезапускает симуляцию по событию вместо остановки. Отключается настройкой
«Шкала времени под сценой».

## Соглашения

- Все скрипты в строгом режиме (`'use strict'` в каждом файле — код исторически
  писался как ES-модуль, семантика сохранена).
- Top-level `const`/`let` классических скриптов разделяются между файлами
  (общая глобальная лексическая среда) — поэтому «импортов» нет, а порядок
  подключения важен.
- Новая симуляция = новый ключ в `Object.assign(SIMS, {...})` подходящего
  файла раздела (или новый файл + строка в `index.html`), плюс привязка
  через `sim:'id'` в формулах/задачах темы.

## Режим учителя

`openTeacher()` → `buildVariants()` → `renderWorksheet()` в конце `app.js`.
Собирает контрольную в нескольких вариантах: у каждого свои параметры
симуляций, значит, и свои ответы — списать у соседа нечего, а проверять
можно по одному листу.

Три решения, без которых это не работало бы:

- **Числа печатаются в условии.** На бумаге нет панели параметров, а условия
  на неё ссылаются («значения — в параметрах слева»). Какие именно параметры
  выписать, определяется не разбором текста, а `answerParams()`: `answer`
  вызывается через `Proxy`, и ловушка `get` показывает ровно те ключи, что
  функция прочитала. Что на ответ не влияет — не печатается. У задач с
  постоянным ответом (работа силы натяжения ровно ноль) список пуст, и блок
  «Дано» не выводится: числа там стоят прямо в условии.
- **Параметры перебираются до осмысленного ответа** (`solvableParams()`).
  Случайный набор сплошь и рядом даёт «события не происходит»: брошенное
  вверх тело не останавливается, если его разгоняют. Берётся средняя треть
  каждого диапазона — у краёв слишком часто вырожденный случай.
- **Датчик случайных чисел с явным зерном** (`seeded()`). «Вариант 3» обязан
  печататься одинаково сегодня и через месяц, иначе учитель не сможет
  повторить раздачу или проверить работу по позже распечатанному ключу.

Контрольная — слой `#worksheet` поверх приложения со своими правилами
`@media print`: на бумагу уходит только она. Других правил печати в проекте
нет — печатать интерфейс целиком смысла не имеет.

## Симуляции без времени

У 37 симуляций из 77 от времени не зависит ничего: показания и графики у них
одни и те же на первой секунде и на сотой. Это электростатика, оптика, спектры,
строение атома и ядра — там, где картинка иллюстрирует устройство явления, а не
его ход. Такие симуляции помечены признаком `timeless:true`, и приложение по
нему прячет часы в шапке, шкалу времени, кнопку графиков и запись ленты
состояний (`updateTimeline`, `buildGraphs`, `record` в `app.js`). Движение на
сцене при этом остаётся: электрон по орбите бежит, ток по проводам течёт —
процесс показан, а вот динамики времени у него нет.

Признак не проставлен на глаз: симуляции прогонялись со случайными параметрами
по всем сценариям, и в список попали только те, у которых за 360 кадров не
изменилось ни одно показание и ни одна точка графика. Первая попытка выдала
41 симуляцию, среди них `micro` — но там просто случайные дробные значения
достались целочисленным параметрам, показания стали NaN, и «ничего не
изменилось» получилось само собой.

## Проверка точности (`tests/physics.mjs`)

Отдельный стенд: 504 проверки, в каждой берутся ПОКАЗАНИЯ симуляции и
сравниваются с числом, посчитанным здесь же по формуле учебника. Показания
для этого и годятся — они подписаны физическими величинами, и брать их
надёжнее, чем лазить во внутреннее состояние 77 разных моделей.

Правила, без которых стенд ничего не проверял бы:

- **Эталон считается по независимой формуле**, а не вызовом кода симуляции.
  Иначе проверялось бы, что код равен самому себе. По той же причине
  константы (`C` в начале файла) выписаны заново: если в симуляции опечатка
  в `ε₀`, сверка её покажет.
- **Параметры некруглые.** На умолчаниях легко получить случайное совпадение
  (ноль, единица), а неверный коэффициент проявляется только на «неудобных»
  числах. Так нашёлся множитель 0,5 в силе Лоренца.
- **Допуск обоснован для каждой проверки.** Алгебра сверяется с `1e-9`,
  результат интегрирования движения — с `1e-3…1e-2`, а там, где разброс
  статистический (конечное число доменов или молекул), допуск выведен из
  числа частиц и записан в комментарии рядом. Округления учебника (`k = 8,99·10⁹`,
  `R = 8,314`) ловятся допуском `1e-4`: он пропускает округление и не
  пропускает ошибку.

### Законы сохранения

Их нельзя проверить одним показанием в конце: полсекунды роста и полсекунды
падения дадут на концах ноль. Поэтому у проверки бывает флаг `traceRO` —
показания записываются на каждом кадре, — и помощники:

- `EX.drift(подпись, имя[, масштаб])` — наибольшее относительное отклонение
  величины от начального значения по всем кадрам. Третий аргумент нужен для
  величин, тождественно равных нулю (проекция импульса поперёк удара):
  нормировать их на собственный шум бессмысленно, масштаб берётся по другой
  подписи.
- `EX.growth(подпись, имя)` — наибольший РОСТ. Для величин, которым разрешено
  только убывать: механическая энергия при трении, кинетическая при
  неупругом ударе. Это ловит «подкачку» энергии интегратором, которой на
  картинке не видно.

Поле `extra` — исходный текст функции `(st, p, hist, out, ro, histRO)`,
выполняемый в браузере. Через него же считаются величины, которых нет в
показаниях: радиус нарисованной траектории, разброс модуля скорости,
отношение двух показаний.
