# Архитектура Phy.Sim

Phy.Sim — статическое браузерное приложение без сборки: обычные `<script defer>`
подключаются в строгом порядке и разделяют одну глобальную область видимости.
Это осознанное решение: пособие должно открываться двойным кликом по
`index.html` на любом школьном компьютере, без Node, бандлеров и сервера
(ES-модули с `file://` не работают из-за CORS, классические скрипты — работают).

## Слои и порядок загрузки

Порядок `<script>` в `index.html` — это и есть граф зависимостей (каждый слой
видит всё, что объявлено выше):

```
KaTeX (CDN, defer)          рендер формул; приложение работает и без него
js/core.js                  хелперы ($, clamp, константы) + пустой реестр SIMS
js/sims/*.js                каждый файл регистрирует симуляции: Object.assign(SIMS, {…})
js/topics.js                учебный контент: T_* темы → SECTIONS → ALL
js/app.js                   ядро: состояние, холсты, рендер-цикл, весь UI
```

Файлы симуляций между собой не связаны и могут подключаться в любом порядке;
важно лишь, что `core.js` идёт первым, а `topics.js` и `app.js` — последними.

## Контракт симуляции

Каждая симуляция — запись в реестре `SIMS` (объявлен в `core.js`):

```js
SIMS.id = {
  title,
  params: [ {key,label,unit,min,max,step,default}
          | {key,label,type:'check',default}
          | {key,label,type:'select',options:[{v,t}],default}
          | {key,type:'group',label} ],          // визуальный разделитель
  init(p) -> state,                              // state.t — время, обязательно
  step(s, dt, p),                                // s.__stop='текст' → таймер встаёт
  draw(ctx, s, view, p),                         // мировые координаты, y вверх
  fit(p, {W,H}) -> {x,y,scale},                  // стартовый вид
  // необязательные расширения:
  graphs, presets, ctxTools, makeOutput, undoAction, …
}
```

`view` (объект `VIEW` из `app.js`) даёт симуляциям утилиты рисования:
`view.label(...)` — подписи, `view.c('--var')` — цвета из CSS-темы,
`view.lw(px)` — толщины линий с учётом зума.

Состояние выполнения (`RT[id]`) создаётся лениво в `rt(id)`: параметры,
state, вид, история Undo/Redo, пометки инструментами.

## Учебный контент (`js/topics.js`)

Тема: `{id, ch, title, theory (HTML), formulas:[{tex, note, sim?}],
problems:[{level, statement, sim?, answer(params), unit, hint?}]}`.
Темы группируются в `SECTIONS` (раздел может быть помечен `hard` — повышенная
сложность), «плоский» список — `ALL`. Ответы задач считаются от текущих
параметров привязанной симуляции — условия «живые».

## Ядро (`js/app.js`)

- **Состояние** `S` + persistence в `localStorage` через обёртку `LS`
  (ключи с префиксом `physim.`).
- **Холсты**: `#scene` (сцена) и `#overlay` (пометки/измерения) с учётом
  devicePixelRatio; рендер-цикл с фиксированным шагом физики `DT = 1/240 c`
  и множителем скорости времени.
- **UI**: дерево тем, конспект/задачи, панель параметров, графики, пресеты,
  полноэкранные настройки, горячие клавиши, запись WebM.
- **Ввод на сцене** — Pointer Events на `#cwrap`: панорама/рисование/захват
  точек одним указателем; зум колесом/тачпадом к курсору (`wheel`); зум
  двумя пальцами (пинч) на сенсоре — активные касания копятся в `Map`
  `touches`, при двух указателях включается режим `pinch`, который
  масштабирует к середине между пальцами и панорамирует её сдвигом (та же
  математика «держим мировую точку под курсором», что и у колеса). Работает
  благодаря `touch-action:none` на канвасе.
- **Раскладка**: десктоп — конспект и симуляция бок о бок со сплиттером;
  ≤900px — симуляция ложится поверх конспекта (`position:fixed`) и
  закрывается кнопкой «назад» (`#btn-simback`, показывается только в этом
  медиазапросе; управляется классами, не inline-стилями — см. историю бага
  в комментарии у правила `#btn-simback` в `css/style.css`).
- **Мобильное управление** (≤900px): полноэкранная сцена перекрывает верхнюю
  и нижнюю панели десктопа, поэтому управление вынесено в отдельный слой,
  скрытый на десктопе (`.mobile-only`, `.mdock`, `.msheet-*` → `display:none`
  по умолчанию, включаются в медиазапросе):
  - слим-шапка `.simhead`: `[‹ назад]  Название ▾  [⚙ настройки]  [⋯ меню]`;
  - плавающий док `#mdock`: сброс · медленнее · скорость · быстрее · большая
    Play/Pause · «Параметры». Кнопки **проксируют** на существующие
    обработчики (`$('#btn-play').click()` и т.п.) — логика не дублируется;
    состояние Play и значение скорости зеркалятся в `setPlayIcon`/`setSpeed`;
  - `#simbottom` превращается в выезжающую снизу шторку (`.msheet-open`) с
    графиками и параметрами поверх сцены, с затемняющим фоном `#msheet-bg`;
  - жест: одним пальцем панорама/рисование, двумя — пинч-зум (см. выше).
  Одинаково работает в портретной и альбомной ориентации (в альбомной док и
  шапка компактнее — отдельный медиазапрос по `orientation:landscape`).

## Сборка защищённой версии (`build.mjs`)

`node build.mjs` (или `npm run build`) собирает из читаемых исходников
обфусцированную версию в `dist/`:

1. **Склейка.** Все `js/`-файлы конкатенируются в порядке из `index.html`
   (классические скрипты делят одну область — склейка эквивалентна их
   последовательной загрузке).
2. **Обфускация** через `javascript-obfuscator`. Включены только механические,
   надёжные преобразования: переименование имён (`renameGlobals: true` —
   безопасно, потому что в HTML нет инлайновых `onclick`-обработчиков),
   шифрование всех строк в base64-массив (`stringArrayThreshold: 1`) и их
   дробление. **Осознанно ВЫКЛЮЧЕНЫ:**
   - `controlFlowFlattening` и `deadCodeInjection` — душат 240-кадровый
     физический цикл;
   - `selfDefending` и `disableConsoleOutput` — их «самозащитные» инъекции на
     этом объёме кода периодически порождают строку-детектор с непечатаемым
     разделителем и делают бандл синтаксически невалидным.
3. **Гейт валидности.** Результат компилируется через `vm.Script` (как скрипт,
   ровно как в браузере) без исполнения. Обфускация недетерминирована, поэтому
   при неудаче seed перебирается до валидного — битый артефакт уехать не может.
4. **Вывод — ДВА файла:** `dist/index.html` (со встроенным минифицированным CSS)
   и внешний `dist/app.min.js`. Бандл именно внешний, а не инлайновый: строка
   внутри кода может содержать последовательность, закрывающую тег
   (`</script` + пробел/слеш/перенос), — инлайн тогда рвётся HTML-парсером, а
   внешний файл этого класса ошибок лишён.

Защита рассчитана на «обычного школьника», а не на эксперта: клиентский код
принципиально восстановим, обфускация лишь поднимает планку.

## Доступ по паролю (`js/app.js`, `#lock`)

Пособие открывается только по паролю. В коде лежит **лишь SHA-256-хэш**
(`AUTH_HASH`), самого пароля в исходниках нет. Успешный вход пишется в
`localStorage` (`physim.authv1`), поэтому пароль спрашивают один раз на
устройство; «Настройки → Данные → Закрыть доступ» стирает эту запись.

SHA-256 реализован вручную (`sha256hex`), а не через `crypto.subtle`:
последний доступен только в защищённом контексте (https / localhost), а
пособие часто открывают с телефона по http-адресу ноутбука в локальной сети —
там `crypto.subtle` отсутствует. Реализация сверена с эталоном Node на
семи тестовых строках.

Это защита уровня «без пароля преподавателя не открыть», а не криптография:
код исполняется на устройстве ученика и в принципе вскрываем. Обфускация
(`build.mjs`) поднимает планку, но не делает защиту абсолютной. Когда появится
сервер, проверку можно перенести туда — точка расширения одна (`lockInit`).

## Настройки (`PREFS` в `js/app.js`)

Каждый пункт — запись `{cat,key,type,def,name,desc,…}`; `type` — `toggle`,
`select` или `range`. Значения живут в `S.settings`, дефолты — в
`PREF_DEFAULTS`, отрисовка полностью автоматическая (`prefRow`/`renderPrefs`),
поэтому новый пункт добавляется одной записью в массив.

Важно: добавив запись, надо **подключить** ключ к поведению — иначе получится
мёртвый переключатель. Места подключения: `applySettings()` (тема, плотность,
CSS-хуки `data-serif`/`data-dock`/`data-hudside`/`--hudk`), `drawGrid`/`gridStep`
(сетка), `fmt` (точность чисел), `loop`/`resize` (кадры, DPR, плотность точек
графиков), `stopEvent` (пауза на событиях), обработчики зума и `toast`.
Проверить, что мёртвых пунктов нет, можно поиском использований ключа вне
объявления `PREFS`.

## Инструменты сцены

Левая панель (`#rail`) содержит инструменты, общие для всех разделов.
Большинство создаёт **пометки** — записи в `a.annos`, которые рисуются в слое
`#overlay` и отменяются через `Ctrl+Z` (`annSnapshot`/`annUndo`):

| Тип пометки | Инструмент | Что показывает |
|---|---|---|
| `pencil` | карандаш | произвольная кривая |
| `ruler` | линейка | расстояние между точками |
| `dim` | размерная линия | расстояние с выносками, как на чертеже |
| `vector` | вектор | длина и угол |
| `angle` | транспортир | угол по трём точкам (вершина — вторая) |
| `circle` | окружность | радиус и площадь круга |
| `area` | площадь | площадь и периметр многоугольника (формула шнурования) |
| `note` | заметка | текстовая метка на сцене |
| `guide` | направляющая | горизонтальная (Alt — вертикальная) линия отсчёта |

Инструменты-действия пометок не создают: `marquee` (зум обведённой рамкой),
`probe` (координаты и величины в точке, сразу в буфер обмена; симуляция может
дополнить их, объявив `probe(state,params,x,y)`), кнопка «след за телами»
(`S.trace` — рисует путь точек из `anchors()`).

Многоточечные инструменты (`angle`, `area`) копят вершины между кликами,
поэтому `pointerup` **не** сбрасывает для них `a.draft`; набор завершается
двойным кликом, `Enter` (или третьей точкой для угла), отменяется `Escape`.

**Инструменты конкретной симуляции.** Симуляция может объявить `ctxTools(p)` —
раньше они были доступны только в меню по правой кнопке (на телефоне туда не
попасть). Теперь `renderSimTools()` рисует их кнопками в той же левой панели
(`#simtools`), а правая кнопка продолжает работать как раньше.

## Раскладка подписей на сцене

Симуляции ставят подписи вручную пиксельными сдвигами, поэтому на разных зумах
они наезжали друг на друга и уходили за кадр. Раскладка чинится централизованно
в `VIEW.label()`: длинная строка ужимается по кеглю (11→8 px), затем подпись
прижимается внутрь кадра, затем — если она перекрыла уже нарисованную —
сдвигается по вертикали до свободного места. Занятые прямоугольники копятся в
`VIEW._lbl` и обнуляются каждый кадр вызовом `VIEW.labelFrame()` в начале
`drawAll()`. Отключается настройкой «Разводить подписи на сцене».

## Командная палитра

`Ctrl+P` (и кнопка в шапке) открывает единый поиск по темам, симуляциям,
настройкам и командам — `Ctrl+Shift+P` или префикс `>` оставляет только
команды. Источник строится в `cmdkSource()`; поиск нечёткий (сначала точное
вхождение, затем совпадение букв по порядку). Список команд — `CMDS`,
добавление новой команды = одна запись в массиве.

## Соглашения

- Все скрипты в строгом режиме (`'use strict'` в каждом файле — код исторически
  писался как ES-модуль, семантика сохранена).
- Top-level `const`/`let` классических скриптов разделяются между файлами
  (общая глобальная лексическая среда) — поэтому «импортов» нет, а порядок
  подключения важен.
- Новая симуляция = новый ключ в `Object.assign(SIMS, {...})` подходящего
  файла раздела (или новый файл + строка в `index.html`), плюс привязка
  через `sim:'id'` в формулах/задачах темы.
